#+title: site

This file explains =site.el=. Reusable code that any denden site can use lives in =denden/denden.el=. See the top-level =README.org= for how to load and build the site.

* For everyday edits
These are the places to change for common, cosmetic changes. No new Lisp functions are needed for any of them.

- Header link: edit =site-menu-header= (short labels, no icons; "More…" jumps to the footer list).
- Footer and palette link: edit =site-menu-main= (every page, with its icon). The two lists are independent on purpose.
- Curated color scheme (a light and dark family at the top of the palette list): edit =site-color-schemes=. It needs a matching entry in =site-schemes-base16.el=, or a =/* @scheme: */= block in =assets/css/theme.css=. A variant that fails =site-contrast-floor= is dropped at build time, not shown.
- Site title quotes (the tooltip and click toast): edit =site-title-quotes=.
- Social link (shown on the About page through =theme-social-links-grid=): edit =site-social-links=.
- Badge: edit =site-badges=.
- Tag icon (log rows and topic lists): edit =site-tag-icons=.
- Chip colour on one topic-list page: set =#+chip_color: base0E= (any base16 slot) in that file.

* How this file is organized
=site.el= is idlip.in on Denden. From top to bottom:
- Configuration data. Both menus, color schemes, title quotes, social links, tag icons, badges, and footer content. These are plain constants. Edit them directly for cosmetic changes.
- Base16 scheme handling. =site-contrast-floor= and =site-scheme-readable-p= check every scheme (text 7:1, links 4.5:1, accent and headings 3:1). =site-scheme-css= writes the CSS for readable variants only, =site-light-scheme-names= tells the pre-paint script which families have a light variant, and =site-schemes-json= writes the palette list (curated families first, then every readable scheme). It also parses custom schemes in =assets/css/theme.css=, using the =/* @scheme: ... */= comment convention.
- =site-generate-schemes-base16-file=. This regenerates =site-schemes-base16.el=, the committed file with 304 base16 entries. Run it by hand only when the =data/schemes/= submodule updates. No part of the build calls it.
- Code colours (=site-highlight-stylesheet=). This maps each htmlize class to its =--baseNN= token.
- The OG card template (=site-og-card-svg=). A 1200x630 card in the Haki colours of =site--og-colors=: favicon and site title, page address, title, excerpt, tag chips, date and reading time. Run =just og= after a build to turn the SVGs into PNGs.
- Topic lists (=site-topic-groups=) and Pose (=site-pose-entries=). Both read the page's text once with =org-element=, export every description or entry in one batch, and keep the result in the page for the rest of the build.
- Data every page shares (=site--build-data=): the palette script, the light-scheme names and the CSS text, computed once per build.
- The page shell (=site-page-shell=), which calls =theme-baseof= with this site's head and chrome.
- Layouts. =site-render-page= is the default (the home page, or a single page with its TOC, References, See Also, comment box and pager); =site-render-pose-page=, =site-render-topic-list-page=, =site-render-sitemap-page= and =site-render-links-page= serve =#+layout: pose=, =topic-list=, =sitemap= and =links=. Pages with no Org file (section lists, =/tags/=, =/refs/= and their terms, =404.html=) are made in =site-listing-outputs= and rendered with =site-render-section-listing=, =site-render-terms=, =site-render-term= and =site-render-not-found=.
- Outputs. Feeds (=site-feed-outputs=: the main feed carries Log and Pose; =/log/= and =/pose/= keep their own; each tag and ref has an =rss.xml=), legacy redirects (=/posts/= and =/themes/=), the search index, the Wander console files (=wander.js= with =site--wander-colors-script= appended, and =wander-theme.css=), the style sheet bundle with the script and scheme data (=site-asset-outputs=), and OG cards.
- The site itself: one =denden-define-site= form, =idlip-site=, which names the layouts and outputs above.

* Adding things
- A new page kind: write a layout =(defun site-render-KIND (site page pages) ...)= that returns the page's main node, add =("KIND" . site-render-KIND)= to =:layouts= in =idlip-site=, and set =#+layout: KIND= in the Org file.
- A new generated file: write an output =(defun site-NAME-outputs (site pages) ...)= that returns a list of =(URL . TEXT)=, and add it to =:outputs=.
- Code blocks in content can read =denden-current-site=, =denden-current-page= and =denden-current-pages=, and should call only public (=site-=, =theme-=, =denden-=) functions.

* Tests
=site/test/=: =site-test.el= renders a small fixture site through =idlip-site='s own layouts and outputs, in memory; the other files test scheme handling and the OG card. Run them with =just test=, or everything with =just check=.
